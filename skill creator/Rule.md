# 角色资产展示板全局架构与底层元规范 (Rule.md)
## Universal Character Presentation Board Meta-Specification

> **规范地位**：本文件是当前仓库中所有角色资产展示板技能（如游戏资产蓝图 `skill.md`、影视服装圣经 `visdev.md` 及未来派生技能）的**底层元规范（宪法）**。  
> **核心原则**：本规范**只定边界、红线、工程管线与交互契约**，绝不干预具体技能的画幅比例、版式划分与容器形态。

---

## 1. 架构分界体系 (Architecture Demarcation)

系统严格实行 **“元规范治理，技能自由实现”** 的解耦架构：

- **Rule.md（底层元规范）**：定义跨越所有展示板技能的底线思维、认知红线、渲染公理、语法契约与状态机门禁。
- **Skills（具体业务技能）**：依据具体应用场景定义版面细节。
  - **【强制默认 2:3 纵向画幅】**：除非用户显式要求其他比例（如机甲横向展开图要求 16:9，或游戏蓝图要求 1:1/3:4），**所有展示板技能必须统一默认采用 2:3 纵向画幅（800×1200 / 1024×1536）**，保障主体全身大立绘拥有充沛的垂直呼吸深度，从几何上根绝横版挤压。

## 2. 认知与反模式红线 (Anti-Patterns)

### 2.1 杜绝打补丁思维 (Anti-Patching Doctrine)
- **红线**：严禁在提示词或规范中通过临时堆砌否定词（如 `No X`, `Without Y`, `No messy text`）来掩盖底层排版逻辑或架构缺陷。
- **治理原则**：所有视觉秩序必须依赖**正向空间几何约束**、**明确的负空间留白定义**与**清晰的提示词权重**从根本上解决。

### 2.2 杜绝角色硬编码与主观臆造 (Anti-Hardcoding & Zero-Hallucination)
- **红线**：严禁在任何通用技能或模板中硬编码预设具体的角色属性（如写死特定服饰款式、特定材质名称、固定职业身份、固定编号或固定色系）。
- **治理原则**：规范与技能仅定义“特征提取通道与装配槽位”，所有关于角色的外貌、妆造、装备与身份细节，必须 **100% 来源于用户的实际输入**（参考图像素与文本设定），系统只客观提取并转译，绝不凭空臆造。

## 3. 视觉实体与物理空间公理 (Physical & Visual Axioms)

### 3.1 模态守恒公理 (Modality Invariance)
- **核心法则**：**输入决定输出，艺术模态严格守恒**。
- 系统必须 100% 原生继承用户参考图的美术风格与渲染模态（无论参考图为何种艺术风格），严禁模型私自跨风格变异或强行转译（除非用户显式提出风格迁移指令）。

### 3.2 角色实体跨格一致性公理 (Cross-Panel Identity Invariance)
- **核心法则**：**单源实体绑定，严禁局部独立漂移**。
- 多格展示板内的所有子视角（如全身立姿、各角度头雕、微表情阵列、局部特写），必须在提示词底层共享**唯一的拓扑物理锚点**（相同的五官骨骼、瞳色、发型发丝走向、肤色基调与穿戴特征）。严禁将各子模块作为互不相关的独立单元生成，杜绝“同板不同人”。

### 3.3 画框安全边距与防裁切公理 (Edge Margin & Truncation Prevention)
- **核心法则**：**呼吸留白保障，严禁顶格裁切**。
- 无论具体技能采用何种画幅比例（1:1、2:3、3:4、16:9等），必须在提示词中强制声明：
  1. **外围安全边距**：画布最外周必须保留至少 **5%~8% 的安全呼吸边距（Outer Safe Margin）**，严禁元素与文字顶格贴边；
  2. **全身立姿防切保护**：展示板中的全身角色，头顶上方必须确保充裕的 **Headroom（头顶呼吸空间）**，脚底必须保证真实的 **Ground Clearance（落地阴影与留白）**，严禁肢体出幅截断。

### 3.4 全局光影与物理空间连贯性公理 (Global Environmental & Optical Coherence)
- **核心法则**：**全局光影同构，空间重力统一**。
- 同一展示板内的所有视图与陈列构件，必须共享**统一的主光源方向（Key Light Orientation）、统一的色温逻辑与地表接触阴影（Contact Shadows）**，杜绝东拼西凑的拼贴杂乱感。

### 3.5 主视觉核心锚点公理 (Hero Visual Anchor Axiom)
- **核心法则**：**主次绝对分明，严禁全板零件平权**。
- 任何角色展示板必须确立**唯一且占据绝对视觉统治地位的主体全身大立绘（Hero Character Art / Master Appeal Pose）**，其视觉面积与垂直贯通高度必须占据整板的绝对视觉中心（通常占据 30%~45% 空间权重），展现角色最生动、最具代表性的动态与气质。
- 转台多视角、微表情与材质球等技术构件，必须严格作为**次级解构构件**环绕或排布在侧，绝对严禁将所有视角切碎为均等大小的缩略图平铺排列表（杜绝“全是小图、没有主体大立绘”的机械工程陷阱）。

### 3.6 禁绝伪线框拓扑与灰模石膏头公理 (Anti-Clay & Anti-Wireframe Trap)
- **核心法则**：**全板纯全彩守恒，严禁扩散模型生成 3D 拓扑**。
- 扩散模型（FLUX、Midjourney 等）基于 2D 像素去噪，不具备 3D 空间顶点与多边形四边面概念。在任何概念展板与角色动画技能中，**严禁使用 `clay render`, `ambient occlusion clay`, `quad-mesh wireframe topology` 等灰模或线框词汇**。此类词汇必然导致模型生成恐怖谷灰色石膏头像、四宫格重复无生气质感以及面部渔网/蜘蛛网脏噪点。
- 所有展示板中的人体立姿与肖像，必须统一采用 100% 穿衣、带真实光影与次表面散射（SSS）的全彩视觉呈现。

## 4. 提示词工程与渲染语法契约 (Prompt Engineering Conventions)

### 4.1 显式单引号约束 (Explicit Quoted Strings)
- 提示词中所有需要在画面中高保真渲染的 UI 英文、标题字符、名称、代码与特定标签，必须在提示词中使用 **显式单引号 `'...'` 包裹**（如 `'FRONT'`, `'#A31D24'`），强制现代扩散模型进入精确字符排印模态。

### 4.2 纯正向词法原则 (Pure Positive Affirmation)
- 全篇提示词必须使用专业、精确、高审美维度的正向视觉描述词汇。
- 严禁在提示词中插入否定句式，严禁依赖 Negative Prompt 代码块来维系画面基础秩序。

### 4.3 双方案交付契约与纯净底板机制 (Clean Plate Deliverable)
- 为满足专业下游工作流（商业印刷、游戏引擎导入、后期本地化）的高精度排版需求，展示板类技能在交付提示词源码时，应天然支持输出：
  1. **方案 A（一键整板渲染）**：包含所有界面文本与版面排印，用于概念预览与快速直出；
  2. **方案 B（纯净无字底板 / Clean Plate）**：仅渲染纯净的背景几何、角色主体与陈列物，保留高透气排版留白，供专业美术在图形软件（PS / InDesign / Figma）中进行 100% 精确的字体填置。

### 4.4 二维空间拓扑栅格公理 (Spatial Grid Topology Axiom)
- **显式层级空间锚定**：提示词中严禁使用无空间方位的线性平铺容器列表（如仅写 `Container 1, Container 2...`）。必须使用清晰的横向通栏（Tiers / Rows）与纵向并排（Columns）语法明确声明各模块的 2D 几何相对关系，杜绝扩散模型在潜空间中的模块错位漂移。
- **海报化垂直层级（Poster Hierarchy Over Tables）**：个人档案等结构化属性必须采用大刊垂直堆叠排版（小号标签置于上方，大号数值居于下方），严禁编写带有横向冒号对齐的程序员数据库键值对（如 `'Key': 'Value'`），防止模型退化为账单登记表。
- **横向多列物理宽度配额（Width Budget Allocation）**：同一横向通栏内若包含 3 个及以上并排构件，提示词必须为各列显式声明宽度百分比，且对大尺寸物理展示物声明紧凑或工整折叠收纳（如 `compact / neatly folded`），防止单品横向过度扩张将同行尾部构件（如色卡）挤压换行到底栏。

### 4.5 极简纯净十六进制色卡规范 (Clean HEX Swatch Contract)
- 提示词中色卡定义右侧必须严格且仅声明显式单引号纯六位代码（如 `'#DFD1B3'`, `'#8C7E6A'`）。
- **严禁在色卡后添加任何括号中英文名称或自然语言说明**（如严禁写 `'#DFD1B3' (warm jasmine)`），防止扩散模型将说明文字直接打印为画面杂质字符。

## 5. 执行管线与状态机门禁 (Pipeline & Execution Gates)

### 5.1 两阶段函数式解耦管线 (Functional Pipeline Architecture)
任何展示板技能的运行逻辑，必须在内部解耦为标准化两段式管道：

```
                    【用户输入 (参考图像素 + 文本设定)】
                                    │
                                    ▼
                ┌───────────────────────────────────────┐
                │   阶段 1: 视觉反编译器 (Visual Decompiler)  │
                │  (客观解构：模态、主色HEX、结构、道具、质感) │
                └───────────────────┬───────────────────┘
                                    │ 传递结构化元数据
                                    ▼
                ┌───────────────────────────────────────┐
                │    阶段 2: 空间装配器 (Spatial Assembler)   │
                │ (装配进具体 Skill 自主定义的画幅与版面结构) │
                └───────────────────────────────────────┘
```

### 5.2 两轮交互状态机安全门禁 (Execution State Machine Gate)
所有展示板技能必须严格遵循两轮交互生命周期，杜绝越权行为：
- **Turn 1（只读推演与交付）**：
  - 检查输入完整性门禁；
  - 运行视觉反编译并推演元数据；
  - 交付完整提示词源码（方案A + 方案B）；
  - **交付后必须原地停机待命**，绝不私自调用任何生图工具。
- **Turn 2（授权执行渲染）**：
  - 唯有在用户在后续独立消息中给出明确出图指令（如“生成图片”、“直接出图”）后，方可启动生图工具执行渲染。

## 6. 通用工业自检验收清单 (Universal Acceptance Checklist)

任何展示板技能在交付提示词或执行出图时，必须对照以下 7 项通用标准进行快速自检：

- [ ] **1. 反模式审查**：提示词中是否杜绝了所有否定补丁词？是否杜绝了硬编码的角色预设？
- [ ] **2. 模态守恒**：整板美术风格与渲染质感是否与用户参考图 100% 保持一致？
- [ ] **3. 实体一致**：全板多视角、表情与特写是否严格锁定同一角色物理身份？
- [ ] **4. 边缘防切**：四周是否有充裕的安全呼吸边距？全身角色是否有充足的头顶与脚底留白？
- [ ] **5. 光影统一**：各模块是否共享统一的光源方向、色温与真实地表接触投影？
- [ ] **6. 单引号语法**：所有需要渲染的界面字符是否全部以 `'...'` 显式包裹？
- [ ] **7. 状态机履约**：首轮是否严格执行纯提示词交付并等待授权，无越权抢跑？
