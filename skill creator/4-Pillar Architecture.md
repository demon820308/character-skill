# 四位一体技能构建工程模型 (4-Pillar Architecture)
## The 4-Pillar Skill Architecture for Character Presentation Boards

> **定位与宗旨**：本模型是以 [Rule.md](Rule.md) 宪法级元规范为底座，指导开发者或 AI Agent 从零构建**任意题材、工业级可靠、全自适应的角色资产展示板技能（Skill）**的标准工程架构范式。  
> **核心思想**：“宪法守底线，四柱立工程”。任何展示板技能只要配齐这四大构件，即可确保 100% 具备抗脆弱性、零幻觉与生产级交付能力。

## Pillar 1: 版面骨架 (Blueprint & Spatial Skeleton)
**核心职责**：定义该技能专属的物理画幅、容器几何拓扑，以及支持变量插值的双轨参数化提示词模板。

### 1.1 画幅比例锁定 (Aspect Ratio Assignment)
- 依据具体业务场景自主选定最佳黄金画幅，严禁盲目跟随：
  - **影视服化道 / 高级概念档案**（如 [visdev.md](../visdev.md)）：选用 **2:3 纵向画幅**（800×1200 / 1024×1536），为九头身立姿与下半部物理解构预留充足垂直呼吸深度；
  - **游戏次世代资产蓝图**（如 [skill.md](../skill.md)）：选用 **1:1 方版** 或 **3:4 竖版**，适应多角度线框与材质球矩阵；
  - **工业机甲 / 载具透视设定**：选用 **16:9 横版**，适应展开图与多视角机械平铺。

### 1.2 容器几何与信息层级 (Container Geometry)
- 规划明确的功能区块百分比与呼吸留白契约（例如：顶部品牌大标 12%、中栏三视图 50%、下栏物理解构 24%、底部签名小传 14%）。
- 明确各容器的陈列纯洁度（纯视觉陈列区严禁文字与数字，数据区严格使用十六进制 `#HEX`）。

### 1.3 双方案参数化提示词模板 (Dual-Plate Template)
- **方案 A（一键整板渲染模板）**：预设高保真版面渲染词汇，所有 UI 文本使用 `'...'` 显式单引号包裹。
- **方案 B（纯净无字底板 / Clean Plate 模板）**：完全剥离字样，专为专业美术后期在 Photoshop / InDesign / Figma 中无损填字预留高透气版面。

## Pillar 2: 反编译器 (Semantic Decompiler & Input Schema)
**核心职责**：构建结构化特征解析字典，指导大模型客观拆解用户参考图，杜绝主观臆造与角色硬编码。

### 2.1 核心输入门禁契约 (Input Gate Contract)
- 明确必须向用户索取的输入门禁（如：【角色参考图】、【角色名称】、【职业/设定背景】）。未集齐前仅针对性追问，严禁私自编造。

### 2.2 结构化特征提取槽位字典 (Decompilation Schema)
- 强制模型按标准数据槽位（Slots）客观解析输入，例如：
  ```json
  {
    "modality": "从参考图中识别的美术风格模态 (3D/二次元/写实等)",
    "theme_color": "提取参考图中统治级深色 HEX",
    "garment_hierarchy": ["最外层外披", "躯干核心上装", "下装裙裤", "鞋履与护具"],
    "accessories": ["提取 2~4 件专属身份佩饰与功能道具"],
    "macro_foci": ["眼眸", "面颊/下颌", "发丝/头饰", "重工面料肌理"],
    "palette_hex": ["#HEX1", "#HEX2", "#HEX3", "#HEX4", "#HEX5"]
  }
  ```

### 2.3 优雅缺省推演规则 (Graceful Defaulting)
- 用户未填写的非核心元数据（如星座、生日、双语诗意小传、设计宣言），由系统根据职业与角色气质自动推演补齐，绝不反复向用户追问查户口。

## Pillar 3: 黄金基准 (Golden Benchmark & Acceptance Radar)
**核心职责**：沉淀覆盖极限场景的参考图与样片测试集，建立客观量化的验收雷达，确保技能达到工业交付级。

### 3.1 跨模态极限压力测试方法论 (Cross-Modality Stress Testing)
- 技能必须在构建期经过全维度压力测试，证明其对任何复杂输入均具备 100% 的稳健性与零幻觉。测试必须完整覆盖以下四大评价维度（详见独立规范 [Benchmark.md](Benchmark.md)）：
  1. **艺术媒介模态维度 (M1~M6)**：涵盖 2D 日漫赛璐珞、黑白漫画网点、3D 皮克斯、次世代 PBR 游戏 CG、胶片商业写真及传统水墨/油画等非标艺术；
  2. **角色解剖与生理形态维度 (A1~A4)**：涵盖极值全年龄体型（幼童至老者/肌肉超模）、异形亚人种族（角/翼/尾/异瞳）、硬表面机甲赛博义体及拟人兽化生物；
  3. **物理材质与微观质感维度 (P1~P4)**：涵盖超薄半透介质（薄纱/蕾丝/PVC）、高反精密金属（铬/钛/碳纤维）、高密度重工编织（羽毛/锁子甲/刺绣）及动态流体能量；
  4. **跨格多视角拓扑一致性维度 (C1~C3)**：涵盖 180° 正反三视图镜像闭环、2×2 微距与全身细节单源映射、以及微表情极端肌肉形变下的骨骼锁定。
- *(注：全量测试用例指标、典型案例图样与评分准入红线，详见配套专项测试标准：[Benchmark.md](Benchmark.md))。*

### 3.2 黄金基准资产库 (Golden Renders Repository)
- 仓库内常态化追踪一组符合 100% 验收标准的高精样图（如 [assets/](../assets/) 目录下的参考图与对应生成成图），作为技能演进的基准地标。

### 3.3 领域专项验收雷达 (Domain Acceptance Radar)
- 针对该技能特有版式定制专属自检项（如：三视图是否具备真实地表接触投影、表情是否具备肢体手势微动、色卡是否纯十六进制码等）。

## Pillar 4: 交互门户 (Interactive Portal & Documentation)
**核心职责**：构建面向用户与上层系统的交互界面，提供直观的视觉展厅、对话状态机引导脚本与排错手册。

### 4.1 视觉展厅文档 (Visual Showcase Documentation)
- 编写规范的中英双语文档（如 [README.md](../README.md) 与 [README_CN.md](../README_CN.md)），嵌入对比展示图、输入输出示例与架构说明。

### 4.2 两轮状态机对话引导脚本 (Interaction Scripts)
- **输入缺失话术**：专业、礼貌地索取必要参数；
- **交付提示词话术**：源码输出完毕后，**必须输出确认引导并原地停机**，明确告知用户“回复‘生成图片’后方可出图”，严格遵守只读待命契约。

### 4.3 故障排查与微调手册 (Troubleshooting & FAQ)
- 针对下游大模型可能发生的偶发瑕疵（如小文字粘连、边缘贴边、构件错位），提供简单直接的参数微调建议与二次修复指南。

## 四位一体构建自查表 (Developer's Checklist)

开发一个新展示板技能时，按此表核对 4 构件是否完备：

| 构件 | 检查内容 | 达标标准 |
| :--- | :--- | :--- |
| **Pillar 1: 版面骨架** | 画幅比例、容器几何、参数化提示词模板 | 包含完整的方案 A（整板）与方案 B（纯净底板）源码模板 |
| **Pillar 2: 反编译器** | 输入门禁、特征提取字典、缺省补齐逻辑 | 严格做到零脑补、零角色硬编码，100% 依据参考图提取 |
| **Pillar 3: 黄金基准** | 跨模态测试用例、已验证样例图库、验收雷达 | 覆盖多题材真实用例，在 `assets/` 中存有高精基准图 |
| **Pillar 4: 交互门户** | 双语 README、展厅画廊、两轮交互话术脚本 | 具备完整的用户使用指南，严格执行首轮纯提示词待命 |
